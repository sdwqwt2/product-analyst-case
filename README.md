# A/B-тест новой формы оплаты ЖКХ

Решение кейса на позицию продуктового аналитика: анализ A/B-теста новой формы оплаты ЖКХ с автозаполнением реквизитов и рекомендация, запускать ли её на всех пользователей.

## Результат

| Метрика | A (старая форма) | B (новая форма) | Разница |
|---|---|---|---|
| Конверсия «открыл форму → успешная оплата» | 49,8% | 64,4% | **+14,6 п.п.**, 95% ДИ [10,9; 18,3], p < 0,001 |
| Клиенты с ≥ 1 успешной оплатой | 65,6% | 80,4% | +14,8 п.п., p < 0,001 |

Эффект есть во всех сегментах (Android / iOS, Москва / СПб / регионы) и все 4 недели теста; контрольные метрики (попытки на клиента, время до оплаты) не ухудшились.

**Рекомендация: раскатывать новую форму на всех пользователей** с holdout ~5% и мониторингом. Подробно — в отчёте [`report/AB_test_ZhKH_Kurilenko.pdf`](report/AB_test_ZhKH_Kurilenko.pdf).

## Методика

- **Очистка:** исключены пользователь без группы, платёж без `user_id`, платёж с ID вне нумерации и клиент, который видел обе версии формы (нарушение сплита); невалидный возраст (−5, 150) обнулён. Выводы на сырых и очищенных данных совпадают.
- **Корректность сплита:** проверка SRM и баланса групп по устройству, городу и возрасту.
- **Статтест:** рандомизация по клиентам, а метрика — по попыткам (1–4 на клиента), поэтому конверсия считается как ratio-метрика с дисперсией по **дельта-методу** на уровне клиента. Проверка — **бутстреп по клиентам** и **логистическая регрессия** с поправкой на устройство и город и кластерными ошибками.
- **Дополнительно:** пошаговая воронка, сегменты с тестом взаимодействия, недельная динамика, контрольные метрики, MDE.
